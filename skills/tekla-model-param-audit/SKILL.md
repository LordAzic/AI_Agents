# Tekla Model-vs-UI Parameter Audit (.NET Framework 4.8)

## 1. Purpose
Tekla plugin modelling logic evolves (e.g., drive shaft parameters previously owned by a pump body get delegated to a coupling module). Rendering dead parameters in primary UI expanders increases cognitive load and misleads detailers. Run this audit **before** classifying parameters or generating XAML.

## 2. Mandatory Static Dependency Protocol
1. **Inventory Declared Fields:** Scan `*Data.cs` (`StructuresData`) and `AttributeNames` for every `[StructuresField(...)]` property.
2. **Trace Modelling Consumption:** Scan the plugin's `Run()` method and all downstream modelling/geometry helper `.cs` files to identify every field actually read, branched on, or passed into Tekla `ModelObject` creation (parts, bolts, welds, cuts, fittings, classes/colors).
3. **Classify Each Field:**
   - `ACTIVE_GEOMETRIC`: Directly drives modeled dimensions, positions, profiles, or topology.
   - `ACTIVE_COLOR`: Drives Tekla part `Class` / color assignment.
   - `ACTIVE_META`: Drives active non-geometric properties (material, prefix, phase, name, weld/bolt metadata).
   - `OBSOLETE_UNUSED`: Declared in `StructuresData` but never read by active modelling logic (or only inside commented-out / unreachable code).
4. **Emit Audit Table:** Before editing XAML, output a concise Markdown table listing `Active` vs. `Omitted (Unused)` parameters with the reason each unused field was excluded.

## 3. UI Pruning & Contract Safety Rules
- **Primary Categorized UI (Vertical Expanders & 2D Preview):** Include ONLY `ACTIVE_*` fields. Omit all `OBSOLETE_UNUSED` fields.
- **Autogenerated `StructuresField` Tab (Hard Boundary):** NEVER omit fields from the raw `StructuresField` tab. All declared `StructuresData` attributes remain accessible there as an engineering override.
- **Backwards Compatibility & Audit Integrity:** NEVER delete `[StructuresField]` or `[StructuresDialog]` declarations from `*Data.cs` or `*ViewModel.cs` unless the user explicitly asks to break saved `.prm` attribute files. Keeping both intact satisfies `audit_tekla_wpf.py`'s `fields.symmetric_difference(dialogs)` contract check.
